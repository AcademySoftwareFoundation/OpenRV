# Constraints applied to pip's build-isolation environments when installing the packages in requirements.txt.
#
# Packages built from source (notably OpenTimelineIO) get an isolated build environment whose build requirements are resolved fresh from PyPI on every build.
# Those resolutions float, so an upstream release can break a build that has not changed. Pin the ones that matter here.
#
# cmake: OTIO's setup.py runs find_package(Python ... Interpreter Development.Module) using the cmake wheel installed into its isolated build environment (NOT
# the cmake driving the outer OpenRV build). cmake 4.4.1 changed how the pydebug ABI is handled on Windows (Kitware/CMake 84cb7e262), which broke that call
# against our custom debug Python and took out every Windows Debug CI build from 2026-08-05 onward with no OpenRV change.
#
# We adapt to that change rather than avoid it: cmake/dependencies/python3.cmake passes -DPython_FIND_ABI on Windows Debug to declare the pydebug ABI
# explicitly. That hint is only correct for 4.4.1+ -- on 4.4.0 the same flag produces "python311d" instead of "python311_d" -- so the pin and the hint must move
# together. Pinning an exact version keeps the build reproducible instead of tracking whatever PyPI serves that day; raise it deliberately after checking
# FindPython's changelog.
cmake==4.4.2
